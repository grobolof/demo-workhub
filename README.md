Это инструкция для тех, кто пользуется сервисом поиска работы и смотрит, где лежат вакансии, резюме и компании.  
Здесь описано, **где что лежит** и **что происходит по нажатию**.

> **Важно.** Вакансии, компании, резюме, баннеры, города, заявки и пользователи живут в **базе MariaDB** (инфоблоки и пользователи 1С-Битрикс). Поиск вакансий идёт через **Elasticsearch**. Первый запуск берёт базу из `docker/mariadb/db.sql`. Дальше демо можно заново загрузить командой **Восстановить демо**. Экраны сайта — в `frontend/`. Своя логика Битрикс — в `local/`.

## Как открыть

**Сайт** — поиск вакансий на Vue. Публично он открыт на [https://khix.swq.ovh/](https://khix.swq.ovh/). Локально интерфейс слушает порт **5173**: `http://localhost:5173`.

**Админка** — Битрикс. Адрес: `http://workhub.docker.local/bitrix/`. Имя берётся из `APP_HOST` в `.env`.

Имя **`workhub.docker.local`** нужно прописать в `/etc/hosts`:

```text
127.0.0.1 workhub.docker.local
```

Порт **80** — это Битрикс: API `/api/` и админка. Сам экран сайта на этом порту не открывается.

**Поддержка** в админке: логин `support`, пароль `support`.

**Демо на сайте.** Работодатели и соискатели входят почтой вида `имя@demo-workhub.ru` и паролем `demo1234` (`App\Demo\Restorer::PASSWORD`). На форме входа нужно выбрать ту роль, с которой аккаунт создан. Например, соискатель `sofia.petrova@demo-workhub.ru`, работодатель `anna.volkova@demo-workhub.ru`.

Почта на локальном стенде никуда не уходит. Заявка с страницы «Помощь» сохраняется в инфоблок.

## Как устроен экран

Светлая страница на шрифте Manrope. Фон `#f3f5f8`, синий кнопок `#0e4ef3`.

### Шапка

| Часть экрана | Что здесь |
| --- | --- |
| **Логотип** | Знак и слово **WorkHub**. Ведёт на главную. |
| **Город** | Кнопка с текущим городом. По умолчанию **Все города**. Список открывается по нажатию. |
| **Роль** | После входа плашка **Соискатель** или **Работодатель**. |
| **Войти** или **Кабинет** | Гостю — **Войти**. Вошедшему — **Кабинет**. |

На узком экране шапка переносится на две строки. Отдельной нижней полосы нет.

### Главная

| Часть экрана | Что здесь |
| --- | --- |
| **Баннер** | Слайд с картинкой. Поверх — счётчики резюме, вакансий и компаний. Точки переключают слайд. Если слайдов больше одного, они сменяются сами каждые 5 секунд. |
| **Поиск** | Заголовок **Поиск работы**, фраза про выбранный город и поле **Название вакансии**. |
| **Список** | Заголовок с городом или с текстом запроса, строка «сколько показано», сортировка по зарплате и карточки вакансий. Дальше список подгружается при прокрутке. |
| **Подвал** | Колонки **WorkHub**, **Соискателям**, **Работодателям** и строка про исходный код. |
| **Окно про данные** | Снизу справа, пока выбор не сделан: **Согласен** и **Не согласен**. |

### Карточка в списке

| Часть экрана | Что здесь |
| --- | --- |
| **Логотип и название** | Ведут на страницу вакансии. |
| **Зарплата** | Вилка или одна сумма. Тоже ведёт на вакансию. |
| **Сердце** | Избранное соискателя. |
| **Компания, текст, факты** | Название компании, короткий текст, график, место работы и города. |
| **Откликнуться** | Кнопка под карточкой. |

### Вакансия, компания, кабинет

| Часть экрана | Что здесь |
| --- | --- |
| **Вакансия** | Название, зарплата, компания, факты и полный текст. Снизу сердце и **Откликнуться**. |
| **Компания** | Логотип, название, текст «О компании» и вакансии по городам. |
| **Кабинет** | Почта, роль, **Выйти**, фото или логотип, ФИО. У работодателя ещё название, ИНН и описание компании. Ниже вкладки. |

## Сайт

### Шапка и подвал

| Элемент | Что произойдёт |
| --- | --- |
| Логотип | Открывает главную. |
| **Город** | Раскрывает список: **Все города** и города демо. Повторное нажатие, щелчок снаружи или Escape закрывают список. Выбор запоминается в браузере (`workhub-city`) и фильтрует вакансии на главной. |
| **Войти** | Открывает `/login`. |
| **Кабинет** | Открывает `/account`. |
| **Помощь**, **Документация API**, **Условия использования** | Открывают `/help`, `/docs` и `/terms`. |
| **Вакансии**, **Компании** | Главная и список компаний. |
| **Поиск резюме** | Открывает `/resume-search`. |
| **@grobolof** и **исходным кодом** | Открывают профиль и репозиторий проекта в новой вкладке. |
| **Согласен** или **Не согласен** | Прячет окно. Выбор пишется в cookie `workhub_consent` на год и на сервер не уходит. |

### Главная

Пока в поле пусто, подсказок нет. Через 0,3 секунды после ввода список обновляется. С двух символов появляются подсказки названий. Стрелки выбирают строку, Enter подставляет её в поиск. Совпадение с уже набранным текстом в подсказки не попадает.

| Что сделали | Что произойдёт |
| --- | --- |
| Нажали точку баннера | Меняется слайд, адрес страницы не меняется. Наведение мыши останавливает автосмену. |
| Выбрали город | Заголовок и список пересчитываются для этого города. |
| Ввели название | Список показывает вакансии по запросу. Пустой результат: «Ничего не нашлось». |
| Выбрали сортировку | **Без сортировки**, **по возрастанию** или **по убыванию** заработной платы. Список запрашивается заново. |
| Дошли до низа | Подгружается следующая порция, по 10 вакансий. |
| Нажали название, зарплату или логотип | Открывается `/vacancy/…`. |
| Нажали сердце | Гостя уводит на вход и после входа возвращает сюда. Соискатель добавляет вакансию в избранное или убирает её. Работодатель видит текст, что избранное вакансий доступно соискателям. |
| Нажали **Откликнуться** | Гостя уводит на вход. Соискатель отправляет отклик, кнопка становится **Вы откликнулись**. Работодатель видит, что откликнуться могут только соискатели. Повторно та же вакансия не отправляется. |

### Вакансия и компания

| Что сделали | Что произойдёт |
| --- | --- |
| **Все вакансии** | Возвращает на главную. |
| Название компании на вакансии | Открывает `/company/…`. |
| Сердце или **Откликнуться** | То же, что на карточке в списке. |
| Строка компании в `/companies` | Открывает страницу этой компании. |
| Карточка вакансии на странице компании | Открывает вакансию. Название компании на этих карточках скрыто: оно уже в шапке страницы. |

Вакансии компании сгруппированы по городам. Если открытых нет, написано «У компании пока нет открытых вакансий».

### Вход и регистрация

На обеих формах выбирают **Соискатель** или **Работодатель**. Уже вошедшего пользователя форма сразу уводит в кабинет или на адрес из `redirect`.

| Что сделали | Что произойдёт |
| --- | --- |
| **Войти** с верной почтой, паролем и ролью | Открывается кабинет. Если на вход пришли с вакансии, возврат на эту вакансию. |
| Роль не совпала с аккаунтом | Вход не выполняется. Написано, как аккаунт зарегистрирован: соискатель или работодатель. |
| **Зарегистрироваться** | Нужны фамилия, имя, почта, пароль и повтор пароля. Пароль — 6–20 символов, только латинские буквы и цифры. Отчество можно не заполнять. |
| Роль **Работодатель** | Дополнительно название компании и ИНН из 10 или 12 цифр. |
| Пустые поля или разные пароли | Под формой ошибка, аккаунт не создаётся. |
| **Уже есть аккаунт?** / **Нет аккаунта?** | Переключает вход и регистрацию, сохраняя `redirect`. |

### Кабинет соискателя

Вкладки: **Избранное**, **Резюме**, **Отклики**. Пока вкладка не выбрана, открыто избранное.

| Элемент | Что произойдёт |
| --- | --- |
| Фото | Перетаскивание или выбор файла ставит аватар. PNG, JPG или JPEG, не больше 5 МБ. **Удалить** убирает фото. |
| Фамилия, имя, отчество и **Сохранить** | Записывает ФИО. Фамилия и имя обязательны. Кнопка неактивна, пока текст не меняли. |
| **Выйти** | Завершает сессию и открывает главную. |
| **Избранное** | Вакансии с сердцем. Снятие сердца убирает строку из списка. Пустое состояние просит отметить вакансию. |
| **Резюме** | Одно резюме: название, зарплата, описание. **Добавить резюме** есть, пока резюме нет. **Изменить** и **Удалить** правят его. Второе резюме форма не создаёт. |
| **Отклики** | Вакансии, на которые уже откликнулись. Список тоже подгружается при прокрутке. |

### Кабинет работодателя

Вкладки: **Вакансии** и **Резюме**. По умолчанию открыты вакансии. Формы резюме соискателя работодателю недоступны: адрес возвращает в кабинет.

| Элемент | Что произойдёт |
| --- | --- |
| Логотип компании | Тот же выбор файла, что у аватара: PNG, JPG или JPEG, до 5 МБ. |
| Название, ИНН, описание | **Сохранить** пишет компанию вместе с ФИО. Пустые поля и ИНН не из 10 или 12 цифр не сохраняются. |
| **Добавить вакансию** | Форма: название, описание, заработная плата, место работы (**Офис**, **Гибрид**, **Удалённо**), график (**5/2**, **Плавающий**, **Вахта**). |
| Карточка своей вакансии | Открывает список откликов: имя, название резюме и время отклика. |
| **Изменить** | Та же форма вакансии. **Удалить** спрашивает подтверждение и убирает вакансию. |
| Строка отклика | Открывает резюме соискателя: почта, телефон и текст резюме. **К вакансии** возвращает к списку откликов. |
| **Резюме** | Избранные резюме работодателя. Сердце снимает резюме с этого списка. Пустой список отправляет в поиск резюме. |
| **Поиск резюме** | Поле «Должность или навык». Гость и соискатель видят, что поиск доступен только работодателям. Сердце добавляет резюме в избранное работодателя. |

### Помощь

Текст на странице коротко повторяет, как искать вакансии и кто что видит в кабинете.

| Что сделали | Что произойдёт |
| --- | --- |
| Заполнили email, тему и сообщение и нажали **Отправить** | Заявка сохраняется. Форма очищается, появляется «Заявка отправлена». |
| Прикрепили файлы | Необязательно. Только PNG, JPG и JPEG, не больше 10. **Убрать** снимает файл до отправки. |
| Не заполнили обязательное поле | Заявка не создаётся, под формой ошибка. |

## Админка

Адрес: `http://workhub.docker.local/bitrix/`.

Команда **Восстановить демо** стоит отдельным пунктом левого меню админки и открывает `workhub_demo_restore.php`. Её видят администратор и группа поддержки. Кнопка спрашивает подтверждение, затем удаляет компании, вакансии, резюме, баннеры, заявки, города, избранное, отклики и всех пользователей, кроме `admin` и `support`, и создаёт демо заново. Пароль работодателей и соискателей после этого снова `demo1234`. Та же команда из консоли: `make demo-restore`.

Поддержка видит список пользователей без правки карточки: ссылки редактирования в списке сняты, страница правки пользователя возвращает к списку.

| Раздел | Зачем |
| --- | --- |
| **Восстановить демо** | Заново загрузить демо-данные. |
| **Инфоблоки типа WorkHub** | **Вакансии**, **Компании**, **Резюме**, **Города**, **Баннеры**, **Заявки**. |
| **Пользователи** | Соискатели, работодатели, `support` и `admin`. |

Пароль пользователя `admin` в эту инструкцию не входит: его задают при установке и хранят отдельно.

## Запуск

Нужны Docker и файл `.env` в корне репозитория. Его собирают из `.env.example`.

В `/etc/hosts` добавляют строку `127.0.0.1 workhub.docker.local`, затем:

```bash
make up
```

`make up` собирает и поднимает контейнеры. При первом запуске база заполняется из `docker/mariadb/db.sql`. Повторный запуск этот файл не перечитывает: данные уже лежат в томе MariaDB.

| Сервис | Зачем | Порт на компьютере |
| --- | --- | --- |
| **frontend** | Vue 3 и Vite. Каталог `frontend/` смонтирован в контейнер, команда `npm run dev`. Запросы `/api` и `/upload` проксируются в **application**. | **5173** |
| **application** | 1С-Битрикс 26.150 на PHP 8.5. Корень репозитория смонтирован в контейнер. | **80** |
| **database** | MariaDB, образ `mariadb`. В ней инфоблоки, пользователи и настройки. | **3306** |
| **elasticsearch** | Elasticsearch 8.19. Индекс вакансий `workhub-vacancies`. | **9200** |

Остановить контейнеры: `make stop`.  
`make down` удаляет контейнеры и тома. Следующий `make up` снова загрузит `docker/mariadb/db.sql`.

Экраны лежат в `frontend/src/pages`, оформление — в `frontend/src/styles.css`. API — в `local/routes/api.php` и `local/src`. Восстановление демо — `local/src/Demo/Restorer.php` и страница `local/admin/workhub_demo_restore.php`.

### Переменные `.env`

| Переменная | Зачем |
| --- | --- |
| **`APP_HOST`** | Имя сайта Битрикс. В примере `workhub.docker.local`. |
| **`APP_PATH`** | Куда внутри контейнера смонтирован репозиторий. В примере `/pub/www/app`. |
| **`DB_HOST`** | Имя сервиса базы в Docker, `database`. |
| **`DB_DATABASE`** | Имя базы, в примере `sitemanager`. |
| **`DB_USER`**, **`DB_PASSWORD`** | Логин и пароль базы. В примере `login` и `pass`. |
| **`DB_ROOT_PASSWORD`** | Пароль root MariaDB. В примере `secret`. |
| **`BITRIX_CRON_ENABLED`** | **`1`** — `cron_events.php` запускается раз в минуту. **`0`** — не запускается. В примере `0`. |

Адрес Elasticsearch задан в `docker-compose.yml`: `http://elasticsearch:9200`. Фронтенд ходит в API через `VITE_API_TARGET=http://application` у сервиса **frontend**.

Пароли из `.env` в инструкцию сверх примера не копируйте: боевые значения хранятся только на сервере.

## Частые вопросы

**Где открыть сайт локально?**  
`http://localhost:5173`. Админка и API — `http://workhub.docker.local` после строки в `/etc/hosts`.

**Почему на порту 80 нет экрана с вакансиями?**  
Порт 80 отдаёт Битрикс. Экран собран во `frontend/` и в локальном Docker открывается на порту 5173.

**Какой пароль у демо?**  
У соискателей и работодателей `demo1234`, логин — их почта `@demo-workhub.ru`. На форме нужно выбрать ту же роль, что у аккаунта. Поддержка админки: `support` / `support`.

**Почему вход пишет, что аккаунт зарегистрирован как работодатель?**  
На форме выбрана другая роль. Выберите **Работодатель** или **Соискатель** так, как аккаунт создавался.

**Где избранное?**  
Соискатель: **Кабинет → Избранное**, сердце на вакансии. Работодатель: **Кабинет → Резюме** и сердце в поиске резюме.

**Почему нельзя добавить второе резюме?**  
У соискателя одно резюме. Кнопка **Добавить резюме** пропадает, когда оно уже есть.

**Куда девается заявка с «Помощи»?**  
В инфоблок **Заявки**. Письмо при этом не отправляется.

**Как вернуть демо, если данные поменяли?**  
В админке **Восстановить демо** или в консоли `make demo-restore`. Пользователи `admin` и `support` остаются.

**Нужно ли пересобирать стили после правки `styles.css`?**  
Нет. Vite подхватывает файл. Если браузер держит старую копию, обновите страницу.
